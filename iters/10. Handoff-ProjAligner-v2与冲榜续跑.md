## 3. 对齐器：v1 结论（已完成）

### 3.1 训练

- 基座：Qwen2.5-7B-Instruct（131 已下到 `Atlas-ProjAligner-SFT/models/`）
- LoRA：`output/qwen25-7b-lora-sft-v1/`（`TRAIN_DONE`）

### 3.2 离线评测（Mac MPS，**v1 数据 + v1 权重**）

目录：`Atlas-ProjAligner-SFT/output/eval_mps_dev_v1/`

| 指标 | 结果（dev 1534） |
|------|------------------|
| exact | 50.52% |
| **fields 序精确** | **53.85%** ← 硬契约关键 |
| fields 集合 | 53.98% |
| shape | 91.33% |
| 延迟 | mean ~4.0s / p50 ~3.4s |

错因结构：shape 对但 fields 错占多数（~626）；list↔entity 边界偶发，**对 EX 影响小**（EX 看值多重集，不看列名/shape 标签）。

结论：**v1 学到了形态，没学稳投影列**；根因是标签过细（SQL 表达式字面）+ 全库 schema 噪声，不是训练崩溃。

## 4. 对齐器：v2 数据（已洗，待训）

### 4.1 相对 v1 的变化

| 项 | v1 | v2 |
|----|----|----|
| `fields[].name` | 常为 `COUNT(T2.user_id)` | 短标签：`user_id` + `kind=count`；`COUNT(*)`→`*` |
| 复杂比例 `SUM/COUNT` | 易误标 count | `name=value, kind=col`，shape 仍 scalar |
| 输入 schema | 整库 | **gold SQL 表 + 1 跳 FK** |
| 表前缀 | 有 | 基本清除 |

shape 规则未改（scalar / list / entity / table，见 `LABEL_V2.md`）。

### 4.2 路径

| 用途 | 路径 |
|------|------|
| 本仓产物 | `ReActSqlExp/data/proj_fields_v2/` |
| 训练机副本 | `Atlas-ProjAligner-SFT/data/v2/` |
| 洗数脚本 | `ReActSqlExp/scripts/wash_proj_fields.py`（`--label-version v2 --schema-mode gold_fk`） |
| 单测 | `ReActSqlExp/scripts/test_wash_proj_fields_v2.py` |
| 规模 | train **7619** / dev **1534** / preview100；held-out 题面已剔 |

## 6. 接手后建议节奏

```text
A. GPU 到位 → run_train_v2.sh → Mac 换 v2 adapter
B. eval_mps_http.py 打 data/v2/dev → 记录 fields/shape vs v1
C. 若 fields ≥ ~70% 或 scalar 子集很稳：
     → 本仓实现 ProjectionAligner HTTP client（off|soft|hard）
     → 先 soft / 条件 hard（仅短 scalar）小样本 EX
D. 并行可选：Oracle gold-fields 灌契约，确认投影链路 EX 上限
E. 再全量 held-out smoke A/B：baseline 78% vs +aligner
```

**不要**在 v2 fields 仍 ~50% 时对全量题 hard 契约。

接入时输入形态建议：

- 短期：与训练一致 —— **剪枝 schema（linker 表 + FK）** 拼进 aligner prompt（v2 已按 gold_fk 洗；线上用真实 linker 输出，分布更近）  
- 应用 `LABEL_V2` 规则解析响应；契约只取 `fields` 的 name 序 + kind 提示
