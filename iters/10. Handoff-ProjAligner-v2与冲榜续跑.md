## A.2 必现级训练坑（H20 / 该 torch 栈）

| 症状 | 原因 / 处理 |
|------|-------------|
| 训练中 **`libcublasLt` SIGFPE** 崩 | **序列 pad 过长**。v1 实测：`max_seq` 推到会 pad≥**704** 就炸 → **稳定值 640** |
| flash-attn / sdpa 不稳 | 强制 **`attn_implementation="eager"`** |
| OOM 或奇怪 CUDA 错 | **`per_device_train_batch_size=1`**, `gradient_accumulation_steps=1`（先别加） |
| cublas workspace | `export CUBLAS_WORKSPACE_CONFIG=:4096:8` |
| pad 对齐 | DataCollator `pad_to_multiple_of=64`（与 640 配套）；乱加大 multiple 会抬有效长度 |
| 模型加载 | 曾用 **CPU 载入再 `.cuda()` / device_map** 更稳（脚本以仓库当时版本为准） |
| 超长样本 | tokenize 后 **丢弃 > max_seq** 的行，勿静默截断污染 |

**v2 脚本默认 `max_seq_length=1024`：** 若同卡同栈再 SIGFPE，立刻降到 **640 或 768** 重跑，不要空转抢点。可改：

```bash
# 覆盖示例（在 GPU 机）
cd /data/workspace/Atlas-ProjAligner-SFT
# 编辑 run_train_v2.sh 或直接：
/root/miniconda3/envs/projaligner/bin/python -u scripts/train_lora_sft.py \
  --model "$PWD/models/Qwen2.5-7B-Instruct" \
  --train_file data/v2/taiji_sft_train.jsonl \
  --eval_file data/v2/taiji_sft_dev.jsonl \
  --output_dir output/qwen25-7b-lora-sft-v2 \
  --epochs 3 --max_seq_length 640 --lora_r 32 --lora_targets attn_mlp \
  --per_device_train_batch_size 1 --gradient_accumulation_steps 1
```
